# Lex-Chat: Judicial Intelligence Platform ⚖️

An advanced, metadata-augmented, hybrid Retrieval-Augmented Generation (RAG) platform specifically engineered for high-accuracy analysis and semantic search over Indian Supreme Court judgments. Powered by **DeepSeek-R1** and **LangChain**.

---

## 1. Problem Statement

Legal professionals and researchers face extreme cognitive friction when navigating long-form, complex judicial documents. Standard text extraction tools treat PDF data as continuous raw character streams, resulting in a complete drop of contextual structural elements. Furthermore, generic LLM applications suffer from hallucinations, fail to provide accurate paragraph-level citations, and lack ground-truth indexing over essential metadata such as the presiding bench, case metrics, jurisdiction timeline, or final ruling vectors.

**Lex-Chat resolves these critical limitations through a deterministic engineering approach:**

- **Preserves Document Structure:** Uses legal-specific regular expression parsing to respect original structural layouts.
- **Enforces an Absolute Guardrail:** Eradicates model hallucinations using automated paragraph-level validation checks.
- **Contextualizes Language Prompts:** Integrates automatic metadata injection (Judges, Case Title, Court, Year, Case Type) directly into individual prompt payloads.

---

## 2. System Architecture & Pipeline Workflow

The platform processes unstructured legal documents through an isolated, production-grade data engineering pipeline to enforce absolute data integrity:

### 📑 Phase 1: Data Extraction & Structuring
* **Ingestion Pipeline (`ingestion.py`)** Extracts raw text streams from target files via `PyMuPDF`. It normalizes layout whitespaces and applies regex heuristics to isolate the pure judgment body from preliminary court schedules (e.g., dynamically establishing matching splits around the legal standard marker `VERSUS`).
    * *Output Generated:* `data/processed_data.json`

### 🔪 Phase 2: Hierarchical Layout Partitioning
* **Paragraph Segmentation (`chunking.py`)** Scrubs web watermarks (e.g., Indian Kanoon header arrays) and breaks the judgment text strictly at official paragraph numbers (e.g., `1.`, `17.10.`) instead of arbitrary character limits. This guarantees that each chunk represents a complete legal thought.
    * *Output Generated:* `data/legal_chunks_ready.json`

### 🧠 Phase 3: Semantic Vector Indexing
* **High-Dimensional Mapping (`core_logic.py`)** Maps the structured paragraph chunks directly into LangChain `Document` objects while appending the full operational metadata payload. It generates dense 768-dimensional embeddings using `sentence-transformers/all-mpnet-base-v2` and compiles them into a local, high-precision vector index.
    * *Output Generated:* Saved locally to the `/faiss_index` directory utilizing `IndexFlatL2` tracking.

### 🔍 Phase 4: Intent-Aware Hybrid Retrieval
* **Context Optimization Framework** Executes a compound search logic. It initiates a semantic baseline search using **Maximal Marginal Relevance (MMR)** to secure maximum information diversity ($k=10$, $fetch\_k=30$). If the user's query matches outcome-based intent keywords (e.g., *verdict*, *held*, *ruling*), a custom sorting algorithm overrides the vector weight, dynamically pushing end-of-judgment paragraphs to the top of the context pile.

### 💻 Phase 5: Cognitive Interface Engine
* **Inference & Verification UI (`app.py`)** Launches an interactive Streamlit UI utilizing dual system-prompt personas (**Professional Counselor** vs. **Simplified Citizen Assistant**). It wraps execution structures inside a stateful `RunnableWithMessageHistory` tracker, programmatically strips out internal chain-of-thought tokens (`<think>...</think>`) generated by **DeepSeek-R1**, and maps raw context variables directly into an on-screen **Evaluation & Proof Report**.

## 3. Technical Stack

* 🧠 **Core LLM Backend:** DeepSeek-R1 (Accessed via secure HuggingFace Hub Endpoint Inference)
* ⛓️ **RAG Framework Architecture:** LangChain Orchestration Suite (`core`, `huggingface`, `community`)
* 📦 **Vector Storage Engine:** FAISS (Facebook AI Similarity Search) - Optimized with strict `IndexFlatL2`
* 🔢 **Semantic Embedding Model:** `sentence-transformers/all-mpnet-base-v2` (768-Dimension Dense Vectors)
* 🛠️ **Data Engineering Pipelines:** PyMuPDF (`fitz`), Python Regular Expressions (`re`), Structured JSON
* 🐳 **DevOps & Containerization:** Docker, Docker Compose Engine, Streamlit UI Architecture

## 4. Specialized Operational Features

- **Hierarchical Paragraph Tracking:** Replaces traditional blind chunking boundaries with explicit legal layout tracking, anchoring text blocks to genuine judicial paragraph IDs to prevent data cross-contamination.
- **Dual-Persona System Orchestration:** Supports toggle logic between a strict, technical **Professional Legal Counselor** framework (structured via explicit ISSUES, REASONING, and CONCLUSION vectors) and a plain-text **Simplified Citizen Assistant** interface.
- **Heuristic Evidence Term Boosting:** Intercepts retrieval structures to enforce manual mathematical priority shifts when vital physical artifacts or foundational charges are cited (e.g., *conspiracy*, *weapon*, *assault*, *bomb*).
- **Automatic Context Serialization:** Maintains state tracking across multi-turn interactions using `RunnableWithMessageHistory`, ensuring seamless contextual dialogue management.

---

## 5. Validation Framework & Evaluation Metrics

The system completely removes loose probabilistic guess-work, executing evaluation parameters patterned alongside structural RAG validation metrics:

1. **Citation Groundedness & Faithfulness:** Evaluated by mapping the specific metadata fields appended to the FAISS vectors. The app extracts the exact source paragraph IDs used during the generation step and renders them within an expandable audit trace wrapper, providing a reliable proof mechanism.
2. **Context Precision & Diversity Optimization:** Controlled at the retrieval intersection by enforcing MMR search rules configured with a target parameter $k = 10$ matched against an initial fetch pool of $fetch\_k = 30$ documents. This eliminates duplicate information and maximizes information density within the context window.
3. **System Confidence Scoring:** Tracks spatial retrieval clustering metrics to report high real-time confidence metrics whenever evidence segments successfully cross-reference across distinct historical paragraphs.
